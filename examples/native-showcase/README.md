# Varta Showcase

Інтерактивна демонстрація поточного нативного UI та можливостей ядра.
Інтерфейс написаний типізованим TSX, скомпільований у Wasm і працює
через нативний CPU preview або опціональний GPU backend без WebView та JavaScript-рушія.

`main.tsx` задає дерево через JSX і компоненти `Header`, `CounterCard`,
`EditorCard`, `TypographyCard`, `EngineCard`. `onClick`/`onInput` змінюють
сигнали; TSX-прив’язки оновлюють залежні тексти, значення й класи. L1 у
`reactive.ts` — локальна копія перевіреного ядра з
`examples/uarp-console/src/l1/reactive.ts`, без зміни його логіки. Копія тримає
приклад у межах власного project root. `View.setEffect` підключає L1 до
згенерованих компілятором TSX-прив’язок, `View.mount` монтує дерево.

Стилі зберігаються в `styles.css` та імпортуються як текст на етапі збірки:

```tsx
import { Runtime, effect, signal } from './reactive.ts';
import css from './styles.css' with { type: 'text' };

View.stylesheet(1, css);
```

Імпорти TypeScript-модулів у прикладі явно використовують розширення `.ts`.
CSS входить у Wasm; під час виконання читання файлу стилів не потрібне.

## Нативна доступність — UI-2, 2026-11-03

Новий desktop-host надає системне дерево через AccessKit: назви й стани
елементів, фокус, натискання, редагування та вибір конкретної опції. На macOS
перевірено CPU Debug (`Varta Showcase A11Y Debug.app`) і Metal GPU Release
(`Varta Showcase A11Y-GPU Release.app`): український текст оновлює привітання,
опції оновлюють пов’язаний стан, кнопка запускає JSON/генератор/async-приклад.
Debug також перевірено з Undo, radio/checkbox і зміною розміру вікна.
Окреме захищене поле показує системному API лише маски до й після редагування.

GPU Release-бандл важить 28 976 058 байтів; приріст проти попереднього GPU UI
становить 401 878 байтів. Це розмір пакета, а не споживання пам’яті.
[Хеші збірок, спостереження й межі перевірки](accessibility-checkpoint-2026-11-03.json).
Інкремент UI-2.1 додає `aria-describedby`: ім’я, textarea та select
посилаються на свої тексти підказок через `name-help`, `editor-help` і `topic-help`.
Ці ID потрібні для семантичних зв’язків. Нативні описи змінюються разом із
реактивним станом; назва поля та його опис передаються окремо. Перед побудовою
дерева спостерігач перевіряє загальний ліміт роботи; відмова не завершує додаток.
[Перевірки описів, відмови та відновлення](accessibility-descriptions-2026-11-03.json).

UI-2.2 додає логічні текстові діапазони, межі слів, рядки та виділення через
AccessKit. Позиції точно відображаються на UTF-8 редактора; emoji, комбіновані
символи й CRLF не зміщують заміну тексту. Застарілі діапазони після редагування,
Undo або зміни типу поля відхиляються. Геометрія символів і перенесених рядків,
assistive scrolling, VoiceOver та інші ОС ще потребують роботи й перевірки.
[Перевірки текстових діапазонів і межі підтвердження](accessibility-text-ranges-2026-11-03.json).

UI-2.3 додає координати символів, напрямок тексту, перенесені рядки та правильну
сторону каретки на межі рядка. Паролі використовують ті самі маски видимих
символів, що й малювання. CRLF більше не створює зайвий рядок; вихідне значення
поля залишається незмінним. Адресні перевірки проходять, а системна перевірка нової
`Varta Showcase GEOMETRY Debug.app` поки не підтверджена через тайм-аут інструмента.
[Геометрія, перевірки та хеші збірки](accessibility-text-geometry-2026-11-03.json).

## Браузерна dev-версія поруч із нативною

Той самий `main.tsx` підтримує офіційний browser host Varta. На цьому Mac
підготуйте явно оголошений у конфігурації Arial і запустіть окремий dev-сервер:

```sh
mkdir -p examples/native-showcase/dist
cp /System/Library/Fonts/Supplemental/Arial.ttf examples/native-showcase/dist/Arial.ttf
target/debug/varta dev --target browser --config examples/native-showcase/varta.config.json
```

CLI надрукує локальну адресу з вільним портом. Відкрийте її у браузері,
залишивши нативний `.app` відкритим. Зміни TSX, TS і CSS перебудовуються
та перезавантажують сторінку. Шрифт залишається в ігнорованій папці `dist`;
для іншої ОС потрібно явно надати доступний файл Arial або змінити родину
в CSS і відповідний запис `browser.fonts`.

Без реєстрації браузерний хост не використовує встановлений у системі Arial:
ізоляція шрифтів дає fallback і змінює метрики тексту.

### Порівняння на macOS, 2026-11-03

**Початкове спостереження перед UI-1, історичне.** Відмінності кореня й
box sizing у таблиці нижче виправлені наступним пакетом; оригінальні
значення збережені для порівняння.

Нативний Debug/dev і Chrome запущено одночасно з поточним `main.tsx` та
`styles.css`. У Chrome вручну перевірено лічильник (`0 → 1 → 6 → 11`,
перемикання кроку на 5), checkbox, ім’я `Павло` і залежне привітання,
дописування ` Готово!` в нотатку, Undo/Redo (`82 → 74 → 82` символи),
Tab між полями, вибір теми «Ядро» та запуск прикладу. Нативну поведінку цих
прив’язок раніше перевірено 12 адресними діями; у відкритому dev-вікні
додатково звірено результат ядра. Обидві версії показали:

```text
JSON: Varta, елементів: 3
Генератор: 2 + 3 + 5 = 10
Promise / await: 7
Усі обчислення завершено.
```

| Спостереження | Нативний preview | Браузерний host |
| --- | --- | --- |
| Шрифт | Явно завантажений Arial | Той самий Arial після реєстрації в конфігурації |
| Межі сторінки | Корінь заповнює клієнтську область вікна | Згенерований HTML залишає стандартний зовнішній відступ body 8 px |
| Прокручування | Усередині `.app` з визначеною висотою | Корінь росте за вмістом, прокручується вся сторінка |
| Розміри полів | Хост задає контролам border-box | Input/textarea використовують content-box: задані висота й ширина збільшуються на padding і border |
| Radio, checkbox, select | Власне малювання preview, квадратна рамка radio | Браузерні елементи та системний popup; radio круглий |
| Доступність | У дереві доступності видно лише вікно | Chrome відкриває підписи, ролі, значення й стани контролів |

Різницю кореня перевірено при ширині вмісту 800 CSS px: браузерний viewport
816×616 дає `main` з координатами (8, 8), шириною 800 та висотою 792 px;
нативний корінь при 800×600 обмежений вікном. У браузері також перевірено
вузький viewport 716×600: картки перебудувалися в одну колонку.

Це функціональне й візуальне порівняння. Час команд автоматизації не є часом
реакції UI. Порівнянного заміру від вводу до показу кадру для Chrome і preview
ще немає; наведені нижче нативні заміри підготовки кадру не дають коефіцієнта
різниці швидкості з браузером. Наступні адресні роботи: узгодити геометрію
контролів і кореня browser host, додати доступність preview та вимірювання
повного шляху вводу до показу кадру в обох хостах.

### UI-1 і GPU: актуальний робочий пакет 2026-11-03

Офіційний browser host тепер прибирає зовнішні відступи сторінки, задає
визначену висоту кореня та border-box для контролів. При viewport
800×600, 720×600 і 700×600 зовнішній `#varta-view` має координати (0,0),
розміри viewport і не збільшує сторінку. Статичний stylesheet дозволений
точним CSP SHA-256 hash; `unsafe-inline` не додається.

`?ui-timing=1` вмикає обмежену браузерну діагностику подій і візуальних
змін (hover, focus, scroll). Endpoint — дві можливості animation-frame після
checkpoint; це не вимірювання фізичного дисплея. Нативний endpoint —
постановка вводу в чергу → повернення з presentation, також без scanout.
Worker прокидається від вводу та підтвердження кадру через condition variable;
idle timeout для таймерів та I/O залишається 16 мс.

Опціональний `gpu` backend використовує wgpu/Vello GPU і спільні
layout/shaping/input metadata. У вікні немає GPU readback чи CPU rasterization
за звичайного vector-шляху. Переповнення запису або втрата device переводить
малювання на CPU, зберігаючи Wasm і стан. На Metal примусова втрата GPU
після 10 кадрів зберегла змінений лічильник і подальший ввід `Павло`.
Явне маркування Display P3 та конвертація sRGB виправляють кольори на macOS.

[Запис вимірювань](gpu-ui-checkpoint-2026-11-03.json) фіксує SHA-256 Wasm,
шрифту та виконуваних файлів. Debug і Release пройшли по 26 offscreen
GPU-перевірок на 1×/2×: геометрія точно збігається, середня різниця RGB
становить 0,187–0,477 з 255. Віконна Release-вибірка містить 56 змішаних
input/pointer кадрів: медіана підготовки 1,65 мс, p95 4,46 мс; медіана
черга → presentation-return 6,13 мс, p95 19,80 мс. Один запуск від входу
в хост до першого presentation-return — 1,89 с. Це локальна вибірка M1 Max,
не порівняльний benchmark з Chrome. GPU readback у probe включає копіювання
й очікування та не є часом презентації вікна.

Release `.app`: CPU 24 065 252 байти, GPU 28 574 180 байтів після видалення
налагоджувальних символів; файли та хеші наведені в записі. Обидва Debug
варіанти для порівняння містять один GPU-enabled host. Не виміряні повна
GPU-пам’ять, прийомка інших ОС/пристроїв та фізична затримка дисплея.
Доступність, повний IME/clipboard і ширше малювання залишаються в плані.

Фінальна перевірка пакета: **3202 тести, 0 помилок, 16 ignored**, усі вісім
етапів та незмінні джерела. Звіт:
`target/verification/20261103-182413-ec8q70t8/report.json`.
Додаткова GPU-конфігурація проходить all-target Clippy і 16 тестів хоста.
Нативна автоматизація вікон перестала відповідати після Release-сценарію;
фінальні Debug-вікно, однакові віконні заміри CPU/GPU та resize/visibility
не зараховані як перевірені. Системний семпл показує worker в очікуванні й
обробку активації вікна AppKit, без зафіксованого блокування GPU-коду за 1 с.
`guest_ms` у нативному звіті включає host input/application-step, а не лише
Wasm CPU; при об’єднанні вводів anchor — перший прийнятий worker-ом ввід.
Після gate змінені лише документація та пояснення вимірювань.

GPU-збірки та діагностика:

```sh
python3 examples/native-showcase/build-macos.py --variant gpu --renderer gpu --timings
python3 examples/native-showcase/build-macos.py --variant gpu --renderer gpu --timings --profile release
```

`--renderer cpu|gpu|auto` вибирає backend. Для GPU без попередньої збірки
збірник додає feature; з `--skip-host-build` він перевіряє наявність backend
через `--renderer-info`. Типовий backend залишається CPU. Це внутрішній
GPU renderer UI; API графіки для Wasm/ігор і сумісність Three.js ще не реалізовані.

## Готовий застосунок на цьому Mac

Після збірки відкрийте `dist/Varta Showcase Debug.app` або
`dist/Varta Showcase Release.app` у корені репозиторію.
Папку `.app` можна перенести в інше місце: хост, Wasm і шрифт знаходяться
всередині. Застосунок побудований для поточного Mac; це локальний
експериментальний preview, а не підписаний реліз для розповсюдження.

```sh
python3 examples/native-showcase/build-macos.py
python3 examples/native-showcase/build-macos.py --profile release
open 'dist/Varta Showcase Debug.app'
```

Окремий TSX-варіант може працювати поруч із раніше відкритою демонстрацією:

```sh
python3 examples/native-showcase/build-macos.py --variant tsx
python3 examples/native-showcase/build-macos.py --variant tsx --profile release
open 'dist/Varta Showcase TSX Debug.app'
```

Збірник не перезаписує наявний `.app`. Для повторної збірки вкажіть інший шлях:

```sh
python3 examples/native-showcase/build-macos.py --output 'dist/Varta Showcase 2.app'
```

За замовчуванням збираються локальні `varta` та `varta-preview`.
`--profile debug|release` вибирає профіль хоста; CLI завжди береться з debug.
`--skip-host-build` використовує вже зібраний хост вибраного профілю.
Обидві версії мають окремі ідентифікатори застосунку й можуть працювати поруч.
Arial береться явно з `/System/Library/Fonts/Supplemental/Arial.ttf` цього Mac
та копіюється лише в ігноровану Git локальну збірку. Шрифт не включений у
вихідний код. Пакет не потребує мережевих, файлових чи clipboard-дозволів.
Хост preview запускає демонстрацію без capability grants; маніфест у Resources
збережений для діагностики, а не завантажується production launcher-ом.

## Що спробувати

- `+`, `−`, скидання та перемикання кроку 1/5.
- Наведення змінює фон і рамки кнопок, полів та перемикачів; утримання
  основної кнопки миші показує стан натискання. Курсор відповідає елементу.
- Checkbox підсвічує картку.
- Ім’я одразу змінює привітання; textarea підтримує український текст,
  виділення, переноси та Undo/Redo.
- Select відкриває список і змінює підпис вибраної теми.
  Рядок під курсором підсвічується без зміни вибраного значення.
- Кольоровий inline-фрагмент переноситься разом із сусіднім текстом.
- «Запустити приклад» виконує типізований JSON decode, генератор і Promise
  з `async/await`; результати малюються після відновлення виконання.
- Tab/Shift+Tab, Space і стрілки працюють з елементами керування.
- Колесо миші прокручує сторінку. При ширині до 720 CSS px картки
  перебудовуються в одну колонку.

## Адресна перевірка

З кореня репозиторію, після збірки CLI:

```sh
python3 examples/native-showcase/verify.py
```

Перевірка запускає справжній застосунок через `varta dev --view-script`,
виконує 12 довірених дій та перевіряє підсумкові значення і результат async.
Вона не замінює візуальну перевірку чи повну платформну прийомку.

Початковий кадр без вікна можна отримати спільним діагностичним прикладом:

```sh
target/debug/examples/headless_frame \
  examples/native-showcase/dist/showcase.wasm \
  examples/native-showcase/dist/showcase.manifest.json \
  /System/Library/Fonts/Supplemental/Arial.ttf Arial target/showcase-initial
```

Для Linux/Windows зберіть Wasm цим самим конфігом і запускайте `varta-preview`
з явно переданим шрифтом родини Arial. Прийомку цих платформ цей приклад
не заявляє. Системні інтеграції та production shell не є частиною цієї
демонстрації; браузерний запуск описано вище.

## Поточна швидкодія

Початкова debug-версія будувала кадр за приблизно 175 мс при масштабі 1 та
242 мс при масштабі 2 (800×600 CSS px). Preview тепер зберігає результати
обчислення стилів і компонування тексту, контури гліфів та команди малювання,
перемальовує пошкоджені ділянки й повторно використовує готові RGB-пікселі.
Код Varta в debug залишається без оптимізації з увімкненими перевірками;
графічні залежності tiny-skia оптимізовані також у dev/test із SIMD. Невеликий
віконний хост використовує opt-level 3 для підготовки RGB-пікселів, зберігаючи
debug assertions та інформацію для налагодження; ядро залишається opt-level 0.

Для відтворення замірів обох профілів використовуйте `frame_timing` із
`--retained --verify --samples=24`, цією Wasm-програмою та Arial. Сценарії:
`increment`, `name --type=а`, `editor --type=а`, `app --scroll=40`,
`increment --pointer`. Числові ID не використовуються як стабільні селектори.
Діагностика
відокремлює гостеві події від побудови кадру, перевіряє точний збіг пікселів
і метаданих та окремо показує перший кадр із холодними кешами. Деталі:
`crates/varta-desktop/README.md`. Ці заміри не включають час показу вікном
і не означають платформну прийомку Linux/Windows.

Базовий прогін перед переходом на TSX і pointer-стани, 2026-11-03,
800×600 CSS px, Arial: медіана повторного кадру, мс.

| Сценарій | Debug 1× | Debug 2× | Release 1× | Release 2× |
| --- | ---: | ---: | ---: | ---: |
| Лічильник | 5.91 | 6.13 | 0.98 | 1.44 |
| Поле імені | 6.79 | 9.14 | 1.26 | 2.63 |
| Textarea | 8.18 | 10.41 | 1.79 | 3.27 |
| Прокручування | 10.16 | 16.36 | 4.58 | 10.28 |

Час включає побудову кадру, конвертацію змінених RGBA-пікселів у RGB та
копію буфера для вікна. Гостеві події виміряні окремо: близько 1,2–1,3 мс
у debug та 0,2 мс у release для редагування/кнопок. У найважчому сценарії
прокручування 2× p95 становить 16,65 мс у debug та 10,64 мс у release.
Перший кадр 1× займає 36–58 мс у debug і 6–8 мс у release; на 2× частина
кешів шрифтів уже прогріта. Показ вікном і очікування екрана не включені.

Кожен сценарій має 24 кадри на масштаб і профіль; усі 384 кадри збігаються
зі stateless-еталоном за всіма пікселями та метаданими вводу. Дані й хеші
збірок збережено у `performance-2026-11-03.json`. Це локальні спостереження,
а не гарантія для інших машин. У готових Debug/Release вікнах також
перевірено введення українського тексту одразу після кліку; у Debug —
прокручування, вибір пункту та результат async/await.

## Перевірка TSX і pointer-станів

У TSX-версії повторно виконано 12 довірених сценаріїв: лічильник, radio,
checkbox, редагування та залежний підпис, select, JSON, генератор і async/await.
43 адресні Rust-тести покривають CSS-matcher, наведення на нащадків, скидання
стану, повторне використання ID, геометрію, курсори, popup, чергу вводу,
інтеграцію runtime та збереження лімітів. Clippy для зачеплених пакетів проходить.

Історичний замір TSX-артефакту до винесення CSS в окремий файл і додавання
браузерної конфігурації шрифту, 800×600 CSS px, медіана підготовки
повторного кадру разом з RGB-копією, мс:

| Сценарій | Debug 1× | Debug 2× | Release 1× | Release 2× |
| --- | ---: | ---: | ---: | ---: |
| Hover / натискання / відведення | 8.14 | 8.58 | 1.11 | 1.66 |
| Реактивний лічильник | 6.08 | 6.68 | 0.95 | 1.38 |
| Прокручування | 10.23 | 16.85 | 5.02 | 10.23 |

Цикл `--pointer` змінює тільки CSS-стани й не активує кнопку. Кожен режим має
16 кадрів на масштаб і профіль; усі 192 кадри збігаються з еталоном за пікселями
та метаданими вводу. Дані й хеші виміряних збірок —
`tsx-pointer-performance-2026-11-03.json`. Не включено очікування показу вікном,
період опитування вказівника чи старт застосунку; це локальні спостереження.

Лічильник та результат асинхронного прикладу мають `role="status"` із доступними
назвами. Native host готує цілісне polite-оголошення після зміни їхнього тексту;
звичайне перемальовування його не повторює. Фактичне озвучення через VoiceOver
перевіряється окремо від адресних перевірок планувальника оголошень.
